# تمرین ۱: صفحه شخصی AI-Native — نسخه آماده استقرار (نه تحویل نهایی)

## اجرای محلی

نیازمندی: Node.js 20+؛ هیچ بسته npm خارجی لازم نیست.

```bash
npm test
npm start
```

صفحه: `http://localhost:3000`  |  Health Check: `http://localhost:3000/health`

## داده‌های واقعی و مرزهای اطلاعاتی

- `profile.json`: ۱ پروژه واقعی هفته‌چین، ۴ درس، مهارت‌ها و فهرست فیلدهای قابل‌انتشار.
- `profile.schema.json`: قرارداد JSON Schema مستقل. فیلدهای نام و عنوان شخصی عمداً null هستند.
- `server/guardrails.js`: اعمال allowlist برای فیلدهای قابل انتشار **قبل از تولید پاسخ** و ثبت دقیق فیلدهای خوانده شده.
- `server/intents.js`: تشخیص Intent در حالت بدون کلید مدل.
- `server/resolve.js`: سه درخواست الزامی، سؤال روشن‌سازی، امتناع از جعل اطلاعات و کنترل اختیارات.
- `server/external.js`: API واقعی Open Library برای پیشنهاد مطالعه؛ در صورت قطع ارتباط کتابی اختراع نمی‌شود.
- `server/llm.js`: **اختیاری**، طبقه‌بندی Intent توسط LLM و بازگشت به قواعد ثابت در صورت خطا.

توجه: بدون `OPENAI_API_KEY` و `OPENAI_MODEL` سامانه یک نمونه مبتنی بر قواعد است، نه یک سامانه دارای استدلال LLM. خروجی پاسخ‌ها در هر حالت به منابع منتشرشده محدود می‌شود. کلیدها را هرگز در کد یا مخزن Git قرار ندهید.

## تست قبل از انتشار

```bash
npm test
```

همچنین `GET /profile.json` باید 404 برگرداند؛ این فایل نباید به عنوان فایل عمومی سرو شود. از طرف دیگر، توضیح محدودیت‌ها باید در صفحه دیده شود.

## انتشار روی Hamravesh / Darkube

طبق راهنمای رسمی: https://docs.hamravesh.com/products/darkube/getting-started

1. سورس پروژه (محتوای پوشه حاوی Dockerfile) را در یک Git repository قرار دهید. فقط اطلاعات قابل انتشار را نگه دارید.
2. از https://console.hamravesh.com وارد شوید و اپ جدید از **منبع گیت** بسازید. Repository و Branch را انتخاب کنید.
3. مسیر Dockerfile را در ریشه پروژه بگذارید و **پورت سرویس 3000** را انتخاب کنید.
4. (اختیاری) متغیرهای `OPENAI_API_KEY` و `OPENAI_MODEL` را **به صورت Secret / Environment Variable** تنظیم کنید؛ نه داخل Git.
5. اپ را Build/Deploy کنید و در تنظیمات دامنه/آدرس عمومی، لینک قابل دسترس را فعال کنید.
6. ابتدا URL `/health` و سپس UI و سؤال‌های نمونه را از اینترنت تست کنید.
7. دستور زیر را با **آدرس واقعی سایت عمومی** اجرا کنید:

```bash
npm run check:live -- https://PUBLIC_APP_URL
```

این دستور `submission/traces.json` و `submission/traces.md` را از **پاسخ‌های واقعی اپ آنلاین** تولید می‌کند: Good Answer، Refusal، Clarification و یک تست اضافه اتصال Open Library. اگر Open Library در دسترس نبود، این مورد را حل و دوباره آزمایش کنید. Trace محلی جای Trace واقعی را نمی‌گیرد.

## تحویل استاد

- لینک عمومی Hamravesh و دستورها/گام‌های Git/Deployment.
- `profile.json` + `profile.schema.json`؛ مشخص‌کردن فیلدهای قابل انتشار.
- `submission/traces.md` که از آدرس عمومی گرفته شده باشد، به همراه Good Answer، Refusal و Clarification.
- پیشنهاد خلاقیت: نمایش فیلدهای JSON و API در بخش Trace وب‌اپ.

**مهلت صورت تمرین: سه‌شنبه، ۳ نوامبر ۲۰۲۶.**

## نکته‌های امنیتی

همین فایل JSON فقط داده‌های خوداظهاری‌شده عمومی دارد. اگر اطلاعات محرمانه‌ای اضافه کردید، قبل از Push بررسی کنید. پاسخ‌های API خارجی قبل از نمایش در رابط کاربری با `textContent` و لینک‌های معتبر عرضه می‌شوند. مسیر HTTP صرفاً فایل‌های استاتیک مجاز را سرو می‌کند. این پروژه یک MVP آموزشی است، نه محصولی با ممیزی امنیتی کامل.

## GapGPT API (اختیاری)

در دارکوب بخش **متغیرهای محیطی** این دو Secret/Variable را تنظیم کنید:

- `GAPGPT_API_KEY`: کلید خصوصی GapGPT (به هیچ وجه در Git یا چت قرار ندهید)
- `GAPGPT_MODEL`: شناسه دقیق مدل موجود در پنل GapGPT (مثلاً فقط اگر در پنل تأیید شده باشد، `gpt-4o-mini`)

آدرس پیش‌فرض API طبق پنل GapGPT: `https://api.gapgpt.app/v1`. در صورت نیاز می‌توان `GAPGPT_BASE_URL` را هم تنظیم کرد.

سپس **Redeploy** کنید. بخش Trace مقدار `Intent source` را نشان می‌دهد:
- `gapgpt`: درخواست مدل موفق بوده و Intent معتبر برگردانده؛
- `rules_fallback`: مدل در دسترس نبوده، پاسخ نامعتبر داده یا فراخوانی ناموفق شده، و قواعد داخلی استفاده شده‌اند؛
- `rules`: درخواست محدود/حساس مستقیم توسط قواعد امن پردازش شده یا مدل غیرفعال است.

حتی در صورت موفقیت GapGPT، مدل فقط Intent را تشخیص می‌دهد. پاسخ از داده‌های مجاز و نتایج API خارجی ساخته می‌شود؛ مدل مجاز به اختراع اطلاعات زندگی‌نامه‌ای نیست.
